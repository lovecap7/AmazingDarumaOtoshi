# 共有スクリプトを変更するときのルール（案）

タスク A-01。ネット対戦の作業で、他の人が作ったスクリプトに手を入れるときの決まりの**たたき台**です。
チームで確認して、決まったら「（案）」を外してください。

## 1. 変える前

- **作成者に一言伝える**（チャットでよい）。下の「連絡のひな形」を使う
- 作成者が今そのファイルを大きく直している最中なら、終わるのを待つか、その人に頼む
- できるだけ **自分のフォルダ（suehara/Network/）で済ませる**。他の人のファイルには「呼び出し口」だけを足す
  - 例: イベント・プロパティ・`internal` メソッドを足し、中身の処理は自分のスクリプトに書く

## 2. 書き方

- **追加だけにする**。既存の処理の順番・数値・名前は変えない
- **ローカルの動きは変えない**。ネット対戦のときだけ通る分岐にする
  （例: `if (m_net != null)`、ネット用プレハブにだけ付ける部品）
- 足した所には `// ネット対戦用(suehara)` のように **目印のコメント** を付ける
- 名前・コメントはそのファイルの書き方に合わせる（日本語のコメント、`m_` の付け方など）
- ネット用の部品はローカル用プレハブに付けない。**`*_Net.prefab`（Prefab Variant）** に付ける

## 3. 変えたあと

- **AllStages（ローカル）で1試合遊んで、今までどおり動くか確認する**（タスク A-14）
- 変えたファイルと内容を `Docs/NetworkHandoff.md` の「他の人のスクリプトに足したもの」に書く
- コミットのメッセージに、触った人のフォルダ名を入れる（例: `ネット対戦: DarumaMatch に再戦の呼び出しを追加 (Nakahira)`）

## 4. 連絡のひな形

```
【ネット対戦】〇〇さんの △△.cs に追加させてください
・足すもの: （メソッド名・イベント名など）
・目的: （例: クライアントで HUD を出すため）
・ローカルへの影響: なし（ネット対戦のときだけ通る）
・確認: AllStages で1試合遊んで確認済み
```

## 5. ぶつかったとき

- 同じファイルを2人が同時に直してコンフリクトしたら、**作成者の変更を優先**して、ネット用の追加をあとから入れ直す
- 作成者が「この形にしてほしい」と言ったら、それに合わせる

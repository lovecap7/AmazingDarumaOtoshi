## 1. 作業の進め方（中平の作業でのみ守る）

- **報告・途中経過・質問はすべて日本語**で書く。
- 進め方：ざっくりした指示 → 実装タスクに分ける → 迷う所・あいまいな所を質問する（はい／いいえ／自由回答）
  → タスクを直す → 要件が固まるまで質問を繰り返す → **それから** UnityMCP で実装する。
  新しい依頼でいきなり実装しない。
- **新しく作るファイルは必ず `Assets/Nakahira/` の中**（中のフォルダ構成は自由）。
- 他のメンバーのフォルダ（Assets/Inoue・Assets/Shitaka・Assets/Fujihara など）の既存ファイルは編集してよい。
- プロジェクト設定（Build Settings を含む）は変更してよい。
- **Resources フォルダは使わない・作らない**（Resources.Load も使わない）。参照はシリアライズや Addressables などで。
- ルールのせいで正攻法が使えず、とても遠回りな方法しかないときは、遠回りせずに「ルールを変えてよいか」を聞く。
- プッシュなどは中平が GitHub Desktop で行う（Claude はコミット・プッシュしない）。
- 他のメンバーのファイルを変えたときは、**ローカルプレイの動きを変えない追加だけ**にして、作業の最後に変えたファイル名を報告する（リポジトリの CLAUDE.md のルール）。

- 演出の見た目（線・色・太さなど）は、コードで組み立てるより**プレハブやマテリアルのアセットにして、インスペクターで編集できる形**にする（中平の好み）。

## 2. 環境

- Unity プロジェクトはリポジトリ直下の `AmaizingDarumaOtoshi/` フォルダ（Unity 6000.6.3f1・URP・Input System）。
- Claude からは UnityMCP（MCP for Unity）で Unity エディタを操作する。
  新しい PC でも Unity 側の MCP for Unity と Claude 側の unityMCP サーバーの接続が必要。
  接続確認：エディタの状態（`mcpforunity://editor/state`）が読めて、コンソールにエラーがないこと。
- **UnityMCP が Unity を見つけられない問題**（何度も起きている。中平が自分で直す。Claude は原因と手順を伝えるだけで、勝手に直さない）
  - 症状：Claude が「Unity が見つからない（No Unity Editor instances found／instances が 0）」と言うのに、Unity の MCP for Unity の画面では接続中に見える。
  - 原因：プロジェクトのパス（「こっちが本物のドキュメント」）に日本語が入っている。Unity が書く状態ファイル `~/.unity-mcp/unity-mcp-status-*.json` は UTF-8 だが、
    サーバー（Python）は Windows の既定の文字コード（cp932）で開くので読めず、Unity を見落とす。
  - 直し方：Windows の「環境変数を編集」（ユーザー環境変数）で `PYTHONUTF8` = `1` を新しく作る → **Claude アプリを完全に終了して開き直す**（Unity は開いたままでよい）。
    一度設定すればどのプロジェクトでも効き、`~/.claude.json` が書き直されても消えない。
    （別の方法：`~/.claude.json` の UnityMCP の `"env"` に `"PYTHONUTF8": "1"` を足す。ただし設定し直しで消えることがある）

## 4. プレイヤーの仕様（決定済み。聞き直さない）

コードは `Assets/Nakahira/Player`。チームメイトの試作（Inoue の Player.cs、Shitaka の BlockController）は使わず、一から作った。

- **入力**：ゲームパッドのみ。左スティック移動／A ジャンプ／X 薙ぎ払い／B ショット。カメラは全員共通の見下ろし。
- **入力とロジックの分離**：`IDarumaCommandSource` / `DarumaCommand`。`DarumaCommand.Move` はワールドの XZ（カメラ変換は `DarumaInputHandler` 側）。
  CPU・ネット対戦はこのインターフェースを実装するだけでよい。`DarumaPlayer.SetCommandSource` で実行中に差し替えられる。
- **オンライン**：Netcode for GameObjects を予定しているが後回し。
- **拾う**：空中で落下中（物理ステップ前に vy<0）に触れた積み木は、どんな状態・速さでも拾える（ダメージなし。当たった場所は問わない）。
  積み木は接地判定から除外。地上で横から当たったらダメージ。
- **積む**：落ちている積み木に着地 → 一番下に追加。最大 10 段、超えたら一番上（古いもの）を落とす。高いほど遅い。
- **股抜きショット**：後ろからハンマーで最下段を前へ打ち出す。まっすぐ滑り、壁で反射、奈落へ落ちる。
- **飛んでいる積み木**：減速する。`TumikiBlock.IsHarmful`（Speed ≥ HarmlessSpeed）で攻撃判定の有無が分かれる。
  攻撃判定のない飛んでいる積み木は、壁で反射・他の積み木と弾性衝突（壊れない）・キャラクターに当たると反射（押さない。キャラの質量 20）。
  ハンマーからは落ちている積み木と同じ扱い。StopSpeed を下回ると落ちている積み木に戻る。
- **薙ぎ払い**：右 → 左の横振り。ハンマーが相手の方向を通り過ぎたときに当たる。落ちている積み木はその方向へ飛ぶ。
  飛んできた積み木：先端で捉えると左へ、根元だと右へ。打ち返しの弾速 = 基本 10 × 1.25^打ち返し回数（連鎖でも回数を引き継ぐ）。
  届く距離 ×1.5（HitReachScale）。打ち返した中平は 0.5 秒その弾に当たらない（ReturnImmunityTime）。
- **連鎖**：飛んでいる積み木が積み木（タワーの段も含む）に当たる → 当たられた方が中心同士を結ぶ線の向きに飛ぶ（ビリヤード。速さ v·n）。当てた方は壊れる。
- **脱落**：頭だけの状態で弾かハンマーに当たる、または奈落に落ちる → キャラクターが消えて幽霊が出る。
  - 幽霊：浮く・壁は通れない・ジャンプ／積む／ショットなし・当たり判定なし（弾がすり抜ける）・ゆっくり薙ぎ払う（0.5 秒）・飛んでくる積み木は打ち返せる・頭だけの生存者を脱落させられる。
  - 幽霊が生存者にダメージを与える（積み木を飛ばして・連鎖で当てても可。打ち返した人に手柄が移る）→ 他の全員から一番遠い出現地点に頭だけで復活、1.5 秒無敵。
  - 2 人以上いて生存者が 1 人以下になったら試合終了。終了は復活より優先。
- **ヒットストップ**（スマブラ風）：薙ぎ払いが当たったとき・ショットで、攻撃した側・弾いた積み木・直接叩かれた相手だけがスローになる（全体の timeScale は使わない）。
  震えは見た目だけ（`Visual` 子オブジェクトの `HitStop`。当たり判定は動かない）。値は HammerParams（幽霊は弱め）。スロー中のジャンプは先行入力として保持。
  積み木同士・積み木とタワーの衝突もヒットストップ（速さに応じる。値は TumikiParams）。壊れる側はヒットストップが終わってから砕ける。
  打ち返しのヒットストップは 1 回ごとに ×1.6、上限 2 秒（Lethal League 風）。
- **エフェクト**：積み木が動いている間は煙の軌跡、攻撃判定があるときは炎のオーラ（Shuriken）。
- **調整値は ScriptableObject**（`Assets/Nakahira/Player/Params`）。使うたびに読むので再生中に変えても反映される。
  - `HammerParams`：キャラクターごと（`Hammer_Default`・`Hammer_Ghost`）。中平はキャラごとにハンマーの差をつけたい。
  - `JumpParams`：全キャラ共通（キャラごとの差はつけない）。
  - `TumikiParams`：共通。`GhostParams`：幽霊。

## 7. 不具合の修正（2026-11-11）

### キャラクターが高く飛び上がる（直した・コミット済み `3be9ca8`。中平が遊んで出ないことを確かめた）
- 起きていた所：殴り合いの最中が多かった。
- 原因：ヒットストップ（キャラごとのスロー）の間、Rigidbody の速度を時間の倍率で割り戻していた。
  重なった積み木などからの押し戻し（PhysX）まで 1/倍率 に増えて上向きにたまり、スローが明けた瞬間に真上へ飛んでいた（横は入力で毎回上書きされるので上だけたまる）。
- 直し方（`DarumaCharacter.FixedUpdate`）：前のステップの「本来の速度」と「Rigidbody に渡した速度」を覚えておき、物理で変わった分は割り戻さずに足す。
  スロー中は、衝突で上下の動きを止めることはできても新しく勢いを足すことはできない（`SlowContactVertical`）。スローでないときの動きは前と同じ。
- 調査用（`Assets/Nakahira/Debug/`）：シーン `HighJumpBugTest.unity`＋`HighJumpBugProbe.cs`（状況を並べて上がった高さを測る）、`HighJumpWatcher.cs`（試合中にジャンプより高く上がったら出す）。
- 残した案：キャラの Rigidbody の `maxDepenetrationVelocity` を 2〜3 に下げる（今は不要）。

### 幽霊が壁にめり込んで動けなくなる（直した・コミット済み `12acd51`）
- 原因：幽霊は動く向きに球を飛ばして壁（`ReflectWall`）を調べるので、壁の中からだとどの向きも「距離 0 で当たった」になり、二度と動けなかった。重なるのは次のとき。
  - `StageArea` が外壁の厚みまで含んでいて、場外に落ちたときに寄せる位置が外壁の真ん中になる（92 ステージ中 85）。
  - せり上がった RisingWall（全部「持ち上げる」設定・高さ 2.5m）の上でやられると、床の高さの幽霊は壁の中に出る。
  - 幽霊のいる床パネルが RisingWall としてせり上がる（幽霊は当たり判定がないので押しのけられない）。
- 直し方（`DarumaGhost.cs` だけ。中川さんの `RisingWallGimmick` は変えていない。壁はすり抜けない）
  - 出るとき（`Init`）・出現の演出が終わったとき（`FinishAppear`）・ワープ（`Teleport`）：壁と重なっていたら一番近い空いた場所へすぐ移す（`TryFindFreePosition`。同じ距離なら中心寄り）。
  - 毎フレーム：壁と重なっていたら、一番近い空いた場所へすべるように押し出す（`UpdatePushOut`。その間は操作で動かない）。
  - 調整値：`m_pushOutSpeed`（8m/秒）・`m_freeSearchRadius`（4m）。中平が「すべるように押し出す」「一番近い空いた場所」を選んだ。
- 確かめた結果：テスト用シーンで壁の中・外壁の中・せり上がる塀の上の幽霊が外に出た（ステージの外には出ない）。CPU のゴーストモード 4 試合でエラー 0・壁に重なったままの幽霊 0。
- 調査用：`Assets/Nakahira/Debug/GhostWallWatcher.cs`（幽霊が壁と重なっていた時間を見張る。`GhostWallWatcher.Begin()`、結果は `Summary`）。

### 積み木が壁にめり込んで動けなくなる（2026-11-12 直した・コミット済み `e1b5844`）
- 原因：ハンマーで最下段を弾かれると、その段はキャラの中心から叩かれた向きへ約 1m 先に置き直されてから飛び出す。壁際で壁の方へ叩かれると壁の厚みの中に置かれていた。

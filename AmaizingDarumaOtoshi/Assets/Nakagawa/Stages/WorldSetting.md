元資料は `AmaizingDarumaOtoshi/資料/` の企画書（pptx）・キャラクター設定シート（docx, v0.1）・会話シナリオ草稿（docx, v0.1）・コスト表（xlsx）。
抽出日: 2026-11-10。元資料が更新されたら、この資料も作り直す。
設計時の注意点（AI が起こしがちな失敗とチェックリスト）は、同じフォルダの `StageDesignPitfalls.md` にある。あわせて読む。

情報の確かさ:
- **【確定】** 企画書・コスト表で決まっている仕様、またはすでに実装されているもの。
- **【案】** 設定シート・シナリオ草稿の案。ステージの雰囲気づけには使ってよいが、ゲームの仕様の根拠にはしない。
- 元資料どうしが食い違うときは、**実装（コード）> コスト表 > 企画書 > 設定シート・シナリオ** の順に優先する。

## 1. ゲームの核【確定】

- タイトル: アメイジングだるま落とし。3D 対戦パーティーゲーム、2〜4人の一画面対戦。キャッチコピー「積んで、飛ばして、最後の一人を落とせ！」
- コンセプト: **「積み木」そのものが「体力」と「武器」になる。**
- 試合の流れ: ① 首（だるまの頭）だけでスタート → ② 落ちている積み木の上に乗って積む → ③ 積み木を飛ばす／ハンマーで殴って相手を崩す → ④ 最後の1人が勝ち。
- ルール: 制限時間なし。1人だけ残ったらリザルトへ。
- 盛り上げたい瞬間（ステージで起こりやすくしたいもの）:
  - **連鎖**: 積み木が積み木に当たって連鎖し、思わぬ大崩れ。「自分の一撃 → 連鎖 → 相手が崩れる」の爽快感。
  - **打ち返し**: 飛んできた積み木をハンマーでギリギリ打ち返す。避けるだけでなく「返す」ことで逆転できる。打ち返すほど弾速が上がる。
  - **漁夫の利**。
  - 配信映え: 誰が見ても状況が伝わる、派手な瞬間。
- 操作: A＝ジャンプ、B＝ハンマーを振る（向いている方向）、B＋RB＝積み木を飛ばす（股抜きショット）。

## 2. ステージ設計に効く仕様【確定】

- 積み木の上限は **10個**。積むほど移動速度とジャンプ力が下がり、10個ではジャンプできない。
- 積み木がない状態で攻撃を受けると死亡（脱落）。落下（場外）でも脱落。
- 脱落後は **幽霊状態**（振りが遅く、リーチは普通）。攻撃を他のプレイヤーに当てると復活する。
- 飛ばした積み木は攻撃判定を持ち、**壁で跳ね返る**。他の積み木に当たると砕ける（いわだるの積み木は砕けない）。プレイヤーに当たった積み木は消える。
- 攻撃力1＝積み木を1個落とす。打ち返されたとき、偶数回目の反射で攻撃力が1上がる。
- 積み木の色: 赤・青・緑・黄・虹（どの色としても扱う）。色ごとにキャラのパッシブが反応するので、**ステージの積み木の湧き方はキャラの強さに直結する**。
- 必殺技ゲージ: 積む・ダメージを与えると増える（攻撃の方がたまりやすい。「もっと戦ってほしい」意図）。
- 特殊ブロック（志鷹の担当、実装済み）: 破壊されない・ジグザグ・壁に当たるたび巨大化・周囲を巻き込む爆発・磁石・ホーミング・曲がる など。

## 3. 世界観【案】

- 舞台: **七転高校（ななころびこうこう）だるま落とし部**と、だるま落としの全国大会。校名は「七転び八起き」から。
- 部訓「**一撃入魂**」。今年の目標「**目指せ全国制覇！**」。
- 頭の色: 練習中は全員が黄色い丸顔。勝負の顔になると本性の色の頭に変わる。
- 積み木の色＝それぞれが積み重ねてきたもの。色ごとの能力は、そのキャラの気性の表れ。
- 雰囲気: 熱血の部活もの＋コミカル。食べ物（おにぎり・牛乳・お菓子）、部活の道具（ホワイトボード・横断幕・ストップウォッチ・分析ノート）、和の縁起物（だるま・鳥居・小槌）がモチーフ。
- 他校の校名（巌高校・蛇ノ目学園・王冠学院）は仮。

### 4-2. ギミック（StageBuilder の Ctx のメソッド）

| ギミック名（一覧での表記） | メソッド |
|---|---|
| 扇風機 | `Fan(a, b, dir, length, width, force, speed)`（a〜b を往復し dir へ風を送る） |
| バンパー | `Bumper(x, z, scale)` |
| 回転台 | `Turntable(x, z, radius, clockwise, speed)`（当たり判定がないので下に床が必要） |
| せり上がり塀 | `RisingWall(x, z, size, phaseOffset)` |
| 加速床／減速床 | `SpeedFloor(x, z, size, accelerate)` |
| 移動床 | `MovingFloor(size, mode, speed, wait, points...)` |
| ワープゲート | `WarpGate(x, z, yaw, group, target, selection, orientation, radius)` |
| シューターレーン | `ShooterLane(x, z, yaw, size)` |
| 回転砲台 | `Cannon(x, z, yaw, mode, minAmount, maxAmount)` |

- 地形: `Floor(cx, cz, w, d)`、`Wall(...)`、`Arena(cx, cz, w, d, north, south, east, west)`（床＋指定した辺の壁）。壁の高さは 1.5m。
- 積み木の生成エリア: `AreaRect(x, z, w, d)`、`AreaCircle(x, z, r)`。床の外やギミックにかぶせて置いてよい（床の上の空いている所にだけ湧く）。
- 出現位置: `Spawns(p1, p2, p3, p4)`。
- コスト表のギミック案のうち未実装: **隕石、UFO（ライフ吸収）、巨大工場／ベルトコンベア**。新しいギミックを作るのは別作業（AdditionalGimmickBuilder 側）なので、ステージ設計では既存ギミックの組み合わせを基本にする。

### 4-3. 検証ルール（`Validate` で自動チェックされる）

- 出現位置はちょうど **4か所**。床の上で、ギミック・生成エリアと重ならない。
- 生成エリアは **6か所以上**。置ける割合が低すぎるエリアは警告。
- ギミックの種類は **1ステージ2種類まで**（本編）。
- 回転台は円全体が床の上にあること。
- `MaxBlocks`（場に出る積み木の上限）は既存の本編で 20〜26。
- `Concept`（どんな場所か・地形）と `Flow`（試合がどう展開するか）を日本語で書く。既存ステージの文体に合わせる。

## 5. 設計の指針（資料からの推論。人間の確認待ち）

- 1ステージで「連鎖」「打ち返し」「漁夫の利」のどれかが起きやすい形にする（壁の跳弾、積み木が密集する補給所、乱戦の中心と外周の対比など）。
- 首だけで始まるので、序盤に積み木を拾いに行く動線と、取り合いになる場所を作る。積みすぎると遅くなるので、「重い人が狙われる」状況が生まれる配置がよい。
- 幽霊が攻撃を当てれば復活できるので、脱落者が戦いに戻れる距離感にする。
- 物語の章に合わせるなら、背景は 序章＝Clubroom、第1章＝Ground、第2章＝鳥居のある会場（背景が未作成）、最終章＝Stadium が近い。
- 小物で物語に触れるのはよい（部室の片目のだるま、ホワイトボード「素振り1000回／積み上げ100段／走り込み！」、横断幕「全国制覇！ だるま落とし部」、割れた窓、いわだるの「壁」など）。ただし、ゲームの仕様を物語の都合で変えない。

## 6. 未決・食い違い（設計で前提にしない）

- 企画書の初期案（あかだる「赤3個以上で弾速UP」、へびだる「3種類以上で移動速度UP」）は、実装・コスト表と違う。**実装の仕様を使う。**
- コスト表ではステージは「ステージ1〜8」（中川担当、5〜8は未完）、ステージモデル8種・ステージBGM8曲の予定。一方、実装済みの本編ステージは17個（Stage01〜17）。本編を何ステージにするかは未確定。
- コスト表「ステージ」シートの手描き案: ステージ1＝中央に壁、ステージ2＝中央に穴、ステージ3＝左右に動く扇風機と風の判定・穴。
- 本編の背景が「家の中の物」なのに対し、物語の舞台は部室・グラウンド・大会会場で、両者の関係は決まっていない。
- 起動映像の決勝の相手（白い頭・黒いハンマー、高く積んでいる）とだるきんぐ（2個縛り）の関係は要確認。
- だるまおとしは未実装（見た目・パッシブ未決定）。専用ステージを作るかどうかも未決定。
